## Этап 1. Архитектура (Claude Code)

Сделано: каркас, база и миграции, авторизация, слои с проверкой линтером, каркас серверных действий,
ограничитель попыток, демо-данные, проверка здоровья, тесты трёх уровней, Docker, CI, документация.

Трудности и решения:

- **Next.js 16 отличается от привычного**: middleware стал `proxy.ts`, Cache Components включены по
  умолчанию, чтение сессии обязано быть внутри `<Suspense>`. Решение: агент сначала читает документацию
  из `node_modules/next/dist/docs`, а не полагается на память.
- **Next.js прячет предыдущие страницы, а не удаляет**: сквозные тесты находили поля скрытой страницы.
  Решение: поиск по роли, очистка форм при скрытии; правило записано в CLAUDE.md.
- **Better Auth требует email**, а вход у нас по логину. Решение: служебный адрес в зоне `.invalid`.
- **Внутренний API библиотеки для создания пользователей оказался нестабильным** (новая сигнатура).
  Решение: демо-пользователи создаются через публичную регистрацию, попутные сессии удаляются.
- **Проверка настроек ломала бы сборку Docker** (на сборке нет секретов). Решение: ленивое чтение
  настроек и проверка при старте сервера.
- **Адрес клиента можно подделать** заголовком. Решение: второй лимит попыток — на логин, независимо от адреса;
  демо-вход вынесен из-под него, чтобы его нельзя было «заблокировать» перебором.
- **На машине разработки нет Docker.** Тесты с базой переведены на PGlite; образ Docker собирается в CI/на площадке.
