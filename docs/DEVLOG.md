# Дневник разработки

Рабочие заметки для итогового описания процесса (инструменты, роли агентов, трудности).

## Этап 0. Согласование (до кода)

- Разобрали ТЗ, зафиксировали объём: обязательное из задания + канбан, приоритет, дедлайн, тёмная тема.
- Учли, что проверяющие в России: отказались от Supabase/Vercel, выбрали переносимый стек.
- Вход по логину вместо почты; общая команда; удалять задачу может только автор.
- Дизайн: 10 вариантов макетов в ChatGPT по подготовленному промпту → выбран стиль «Ясность» →
  9 листов (набор компонентов, экраны, состояния, мобильная версия).

## Этап 1. Архитектура (Claude Code)

Сделано: каркас, база и миграции, авторизация, слои с проверкой линтером, каркас серверных действий,
ограничитель попыток, демо-данные, проверка здоровья, тесты трёх уровней, Docker, CI, документация.

Трудности и решения:

- **Next.js 16 отличается от привычного**: middleware стал `proxy.ts`, Cache Components включены по
  умолчанию, чтение сессии обязано быть внутри `<Suspense>`. Решение: агент сначала читает документацию
  из `node_modules/next/dist/docs`, а не полагается на память.
- **Next.js прячет предыдущие страницы, а не удаляет**: сквозные тесты находили поля скрытой страницы.
  Решение: поиск по роли, очистка форм при скрытии; правило записано в CLAUDE.md.
- **Better Auth требует email**, а вход у нас по логину. Решение: служебный адрес в зоне `.invalid`.
- **Внутренний API библиотеки для создания пользователей оказался нестабильным** (новая сигнатура).
  Решение: демо-пользователи создаются через публичную регистрацию, попутные сессии удаляются.
- **Проверка настроек ломала бы сборку Docker** (на сборке нет секретов). Решение: ленивое чтение
  настроек и проверка при старте сервера.
- **Адрес клиента можно подделать** заголовком. Решение: второй лимит попыток — на логин, независимо от адреса;
  демо-вход вынесен из-под него, чтобы его нельзя было «заблокировать» перебором.
- **На машине разработки нет Docker.** Тесты с базой переведены на PGlite; образ Docker собирается в CI/на площадке.

## Этап 1.1. Ревью фундамента двумя независимыми агентами

Роли: агент-ревьюер кода и агент-ревьюер безопасности, оба только на чтение, с разными заданиями;
результаты проверены и исправлены основным агентом. Критичных проблем не найдено. Исправлено:

- **Лазейки в правилах линтера** (относительные пути, файлы вне шаблонов). Правила перестроены
  «от запрета к разрешению» и закреплены 41 тестом.
- **Адрес клиента брался не с того конца `X-Forwarded-For`** — подделывался одним заголовком.
- **В журнал могли попасть параметры запросов** (токены сессий) при ошибке базы.
- **Демо-данные не были атомарными**: сбой на середине оставлял полупустую базу навсегда. Теперь одна транзакция.
- **Не был определён часовой пояс «сегодня»** — в Docker (UTC) «просрочено» ночью считалось бы неверно.
- Добавлены CSP, очистка устаревших счётчиков, подсказка «повторите через N секунд», проверка нулевого символа.

Отдельно поймано проверкой «как в Docker»: сборка без настроек падала, потому что настройки читались
раньше обращения к запросу. Вывод: проверять не только тестами, но и реальным сценарием развёртывания.

## Этап 2. Функции и интерфейс — воркфлоу из 9 агентов

Оркестратор изучил все 9 листов макетов, заранее закоммитил два «контракта» (провайдер окон задач
и индикатор сохранения) и запустил воркфлоу (около 80 минут, 6 этапов):

| Этап              | Агенты                                                                    | Итог                                                    |
| ----------------- | ------------------------------------------------------------------------- | ------------------------------------------------------- |
| Основа            | серверная логика задач ∥ дизайн-система                                   | 130 тестов задач, покрытие модуля 98 %; 20+ компонентов |
| Экраны            | доска, список, фильтры, мобильная версия ∥ окна задач, вход и регистрация | всё состояние фильтров — в адресной строке              |
| Сверка с макетами | один агент, скриншоты 1536×1024 и 390×844 в двух темах                    | 7 исправлений вёрстки                                   |
| Сквозные тесты    | один агент                                                                | 27 сценариев × 2 устройства; найдена ошибка календаря   |
| Ревью             | код и безопасность ∥ UX и доступность                                     | 14 находок (5 средних, 9 мелких), критичных нет         |
| Исправления       | один агент                                                                | все 14 подтверждены и исправлены                        |

Трудности и решения:

- **Параллельные агенты в одной папке.** У каждого своя зона файлов, отдельный порт dev-сервера,
  запрет на общую сборку `.next`, коммит только своих путей. Стыковка — через заранее написанные контракты.
- **Контраст цветов макета.** Серый текст макета на фоне давал 4.17:1 (меньше 4.5 по WCAG AA) —
  дизайн-система затемнила его; ревью доступности нашло ещё приглушённый текст на цветных плашках колонок.
- **Календарь брал фокус на кнопку «предыдущий месяц»** (Radix перехватывал автофокус) — нашли e2e-тесты.
- **Перетаскивание с клавиатуры в тестах** теряло нажатия: dnd-kit не успевал измерить колонки. Тест ждёт
  объявление для экранного диктора, как живой пользователь.
- **«Сегодня» нельзя считать при отрисовке клиентского компонента** (Cache Components ругается) —
  дата считается один раз на сервере и передаётся вниз.
