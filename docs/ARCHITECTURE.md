# Архитектура Teamboard

## Общая схема

Одно приложение (монолит) на Next.js и одна база PostgreSQL. Браузер обращается только к домену
приложения — никаких сторонних сервисов.

```
Браузер ──HTTPS──▶ Next.js (Node.js) ──▶ PostgreSQL
                    │
                    ├─ proxy.ts            быстрый редирект гостя на /login
                    ├─ страницы (RSC)      чтение данных через queries.ts
                    ├─ серверные действия  изменения через actions.ts
                    └─ /api/health         проверка работоспособности
```

## Слои

| Слой             | Где                                                    | Отвечает за                                                     | Не имеет права                                |
| ---------------- | ------------------------------------------------------ | --------------------------------------------------------------- | --------------------------------------------- |
| Интерфейс        | `src/app`, `features/*/components`                     | Отображение, формы, состояние экрана                            | Ходить в базу, вызывать сервисы и репозитории |
| Граница сервера  | `features/*/server/{actions,queries,session}.ts`       | Сессия, проверка ввода, перевод ошибок в `ActionResult`         | Содержать правила и запросы                   |
| Сервисы          | `features/*/server/service.ts`                         | Правила: права, сценарии, ошибки предметной области             | Знать про Next.js и про базу                  |
| Репозитории      | `features/*/server/repository.ts`                      | Запросы к базе, преобразование строк в модели                   | Принимать решения о правах                    |
| База             | `src/db`                                               | Схема, миграции, подключение, демо-данные                       | —                                             |
| Предметная часть | `features/*/{model,schemas,policy}.ts`, `src/lib/*.ts` | Типы, константы, проверки, права — общие для сервера и браузера | Зависеть от фреймворка и серверного кода      |

Границы проверяет линтер (`eslint.config.mjs`, правило `no-restricted-imports`): нарушение — ошибка
в `pnpm lint` и в CI.

### Путь изменения (например, «создать задачу»)

```
Форма ─▶ createTaskAction(input)                       actions.ts
          └ authedAction:
              1. сессия → пользователь (иначе UNAUTHENTICATED)
              2. Zod-схема (иначе VALIDATION + ошибки по полям)
              3. taskService.create(data, user)        service.ts  → правила, права
                   └ taskRepository.insert(...)        repository.ts → SQL
              4. ActionResult { ok, data | error }
```

Действие никогда не бросает исключение в браузер. Непредвиденная ошибка пишется в журнал сервера,
пользователь видит общее сообщение — детали (тексты SQL, адреса) наружу не утекают.

### Путь чтения

Страница — серверный компонент. Данные запрашивает асинхронный компонент внутри `<Suspense>`:
оболочка страницы отдаётся мгновенно, данные подгружаются потоком, на их месте — скелетон.
`queries.ts` сначала вызывает `requireUser()`, затем сервис/репозиторий.

## Структура папок

```
src/
  app/                    страницы и адреса
    (auth)/               вход, регистрация
    (app)/                рабочая часть (после входа)
    api/health/           проверка работоспособности
  features/
    auth/                 вход, регистрация, сессия        ← образец всех слоёв
    users/                участники команды                ← образец репозитория и чтения
    tasks/                задачи: модель, проверки, права  (сервер и интерфейс — следующий этап)
  components/ui/          общие элементы интерфейса (дизайн-система)
  db/                     схема, подключение, миграции при старте, демо-данные
  lib/                    общее: ошибки, результат действия, адреса страниц
  lib/server/             серверное: настройки, журнал, ограничитель попыток, каркас действий
  proxy.ts                предварительная проверка cookie
  instrumentation.ts      подготовка при старте сервера
drizzle/                  SQL-миграции (создаются командой, правятся только через схему)
tests/e2e/                сквозные тесты в браузере
tests/helpers/            база в памяти и авторизация для тестов
scripts/                  миграции, демо-данные, подготовка сборки
```

## Данные

```
users ──┬─< sessions            сессии (токен в httpOnly cookie)
        ├─< accounts            хэш пароля
        ├─< tasks.creator_id    автор (ON DELETE RESTRICT)
        └─< tasks.assignee_id   ответственный, может быть пустым (ON DELETE SET NULL)

tasks: id, title, description, status(new|in_progress|done),
       priority(low|medium|high), due_date(date), assignee_id, creator_id, created_at, updated_at
rate_limits: key, count, window_started_at      счётчики попыток входа и регистрации
```

- Статус и приоритет — перечисления PostgreSQL, созданные из констант `features/tasks/model.ts`.
- Индексы по `status`, `assignee_id`, `creator_id`, `due_date` — под фильтры.
- Ограничения в самой базе: непустое название, длина описания, уникальный логин.
- Порядок карточек в колонке вычисляется (приоритет, затем дедлайн) — ручной сортировки нет,
  поэтому нет и поля позиции и связанных с ним конфликтов.

## Авторизация и безопасность

- Вход по **логину и паролю**; пароль хранится только как хэш (scrypt), сессия — в базе,
  токен — в `httpOnly` cookie (`Secure` при https, `SameSite=Lax`).
- Вход и регистрация идут только через серверные действия; HTTP-адреса библиотеки авторизации
  наружу не опубликованы.
- Ограничение попыток хранится в базе: 10 попыток входа за 10 минут на пару «адрес + логин»,
  30 на логин с любых адресов, 5 регистраций в час с адреса.
- Одинаковый ответ на неверный пароль и на несуществующий логин.
- Права проверяются в сервисе при каждом вызове. Удалить задачу может только автор; менять — любой участник.
- Все входные данные проходят Zod-схемы; запросы к базе параметризованы (Drizzle).
- Заголовки безопасности заданы в `next.config.ts`.
- Секреты — только в переменных окружения, проверяются при старте (`src/lib/server/env.ts`):
  с неверной конфигурацией сервер не запустится.

Допущение: приложение стоит за обратным прокси, который сам выставляет `X-Forwarded-For`.
Если прокси нет, адрес клиента можно подделать — на этот случай действует лимит на логин,
не зависящий от адреса.

## Запуск и развёртывание

- `next build` создаёт самодостаточную папку `.next/standalone` (сервер, статика, миграции).
  Запуск: `node server.js`. Нужны только Node.js 22+ и PostgreSQL.
- При старте (`instrumentation.ts`): проверка настроек → миграции (под блокировкой в базе,
  безопасно при нескольких копиях) → при `SEED_DEMO_DATA=true` демо-данные в пустую базу.
- `Dockerfile` (многоэтапный, запуск не от root) и `docker-compose.yml` (приложение + PostgreSQL).
- `/api/health` — 200, если база отвечает; иначе 503.

## Тестирование

| Уровень        | Инструмент      | Что проверяет                                                             |
| -------------- | --------------- | ------------------------------------------------------------------------- |
| Модульные      | Vitest          | Схемы, права, каркас действий, настройки                                  |
| Интеграционные | Vitest + PGlite | Репозитории, сервис авторизации, ограничитель, ограничения базы, миграции |
| Сквозные       | Playwright      | Сценарии в настоящей боевой сборке, на компьютере и на телефоне           |

PGlite — настоящий PostgreSQL, работающий в памяти процесса: интеграционные тесты не требуют
ни Docker, ни отдельной базы и применяют те же миграции, что и сервер.

## Что строится следующим этапом

Контракты для задач уже заданы (`features/tasks/model.ts`, `schemas.ts`, `policy.ts`, таблица `tasks`).
Осталось по образцу `features/auth` и `features/users`:

| Файл                         | Содержимое                                                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `tasks/server/repository.ts` | `list(filters, today)`, `findById`, `insert`, `update`, `delete`; соединение с `users` для автора и ответственного                  |
| `tasks/server/service.ts`    | `list`, `create`, `update`, `changeStatus`, `delete` + права (`policy.ts`), `NotFoundError`, проверка, что ответственный существует |
| `tasks/server/actions.ts`    | `createTaskAction`, `updateTaskAction`, `changeTaskStatusAction`, `deleteTaskAction` через `authedAction`                           |
| `tasks/server/queries.ts`    | `getTasks(filters)` для страниц                                                                                                     |
| `tasks/components/*`         | Доска, список, карточка, форма, фильтры (состояние фильтров — в адресной строке, `parseTaskFilters`)                                |
| `components/ui/*`            | Дизайн-система по макетам                                                                                                           |
